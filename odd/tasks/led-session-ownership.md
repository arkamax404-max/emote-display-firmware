## Implementation decisions
- Protocol fixed for both independently implemented halves: existing HTTP version/header X-Emote-Version: 1; bodyless POST /emote/claim, /emote/heartbeat, /emote/release with Content-Length: 0. Controls require exactly one X-Emote-Session-Id matching [A-Za-z0-9._:-]{1,128}. Reject malformed/duplicate IDs and invalid controls without mutation. Missing ID is allowed only for legacy PNG, not controls. Keep existing header/body/time limits and PNG validation.
- Control 200 responses carry X-Emote-Ownership: 1 and a small JSON body; sender only reports reservation supported after successful claim with that marker. 404/405 or missing marker use legacy delivery with a warning, not a claimed reservation. Other failures must not report a successful claim. Existing heartbeat behavior remains for loopback destinations.
- Claim replaces RAM owner and timestamps at successful processing. Heartbeat renews owner only, never claims; no-owner heartbeat succeeds without claiming; foreign heartbeat/release returns 409; release without owner is idempotent 200. No persisted reservation; boot begins ownerless. No owner identity exposed in health; additive sessionOwnership: true, ownershipActive and ownershipRemainingMs are sufficient.
- Lease 30000ms via wrap-safe elapsed arithmetic, evaluated before decisions and in loop. Valid owner PNG may renew lease only after successful decode/presentation. Foreign/missing-session PNG while owned returns 409 after consuming declared body, leaving frame count, pixels, image class and 10s clock timer unchanged. Existing sender request counter semantics stay image-attempt-only.
- Only explicit displayOn triggers claim for nonloopback exact /emote URLs without a query and with session identity. Resume preference never claims. Serialize control with per-target delivery; ensure claim precedes new images, displayOff cancels pending images/heartbeats then orders release, and late async completions cannot resume stopped/disposed targets. Repeated explicit displayOn must claim even if already enabled. Heartbeats every 5s while explicitly enabled/claimed, even without an initial image. Ordinary retries may continue after 409, never silently reclaim. Warnings must not claim enforcement on legacy or sessionless targets.
- No authentication/security claim: trusted LAN coordination only. Technical choices above resolve implementation detail, not additional product requirements.
