# Weather screen alternating with the clock

Feature: in clock mode the panel alternates the clock with a weather screen split into a grid showing today and the next three days, with the clock and weather durations, the city and the temperature unit all set from the portal.

## Specs

S1. Objective, from the user (verbatim): "la nueva feature implica al modo reloj, en este modo vamos a intercalar la pantalla del reloj con otra con informacion climatologica, vamos a dividir la pantalla en una cuadricula mostransdo el tiempo para hoy y la prevision de los proximos 3 días, usa una linea vertical y horizontal para la division. El tiempo que permanece el reloj y el tiempo lo haremos configurable en el portal, asi como la seleccion de la ciudad y si la temperatura va en grados celcius o farenhei"

S2. City selection, user decision: "Texto libre con geocodificacion" — the portal takes a city name, resolves it with the geocoding API and stores the resulting latitude and longitude.

S3. Cell content, user decision: "Temperaturas y probabilidad de lluvia" — no icons; each cell shows the maximum and minimum temperature and the precipitation probability.

S4. Durations, user decision: "Reloj 20 s / tiempo 10 s" as the defaults, both configurable from the portal.

S5. TLS, user decision: "Sin validar el certificado" — the connection skips certificate validation, accepting that someone on the local network could intercept or forge the forecast. The data is not secret; the risk is accepted and recorded in the documentation.

S6. Ciudad por defecto, del usuario (verbatim): "la ciudad por defecto será Sevilla" — una placa recién grabada, sin configurar nada, debe mostrar el parte de Sevilla en lugar de no mostrar nada.

S7. Revisión de la maquetación de la celda, del usuario (verbatim): "yo pondria el 10% de lluvia arriba en la misma linea que el día de la semana alineado a la derecha, el numero grande y el pequeño dime si es la temp maxima y minima y si lo son prefiero que tengan el mismo tamaño, y por ultimo echo en falta algo de iconografia". La probabilidad de lluvia va en la fila del día, alineada a la derecha de la celda; la máxima y la mínima se dibujan al mismo tamaño (escala 2) y el número grande es la máxima.

S8. Iconografía, del mismo mensaje: cada celda muestra un icono de 8x8 derivado del código meteorológico WMO de Open-Meteo, situado a la derecha de las temperaturas. Si una temperatura ocupa tres dígitos y no cabe junto al icono, el icono se omite en esa celda antes que recortar una cifra.

S9. Tercera revisión visual, del usuario (verbatim): "los iconos hay que moverlo 3 o 4 px a la izquierda, quitamos tambien las lineas de separacion y para las cifras negativas usaremos un azul intenso en lugar del signo menos". Los iconos se desplazan 4 px a la izquierda dentro de su celda; desaparecen las dos divisoras, horizontal y vertical; una temperatura negativa se dibuja sin signo menos y en azul intenso, de modo que el color codifica el signo.

## Implementation decisions

- Provider: Open-Meteo, free and keyless. Forecast `https://api.open-meteo.com/v1/forecast` with `daily=temperature_2m_max,temperature_2m_min,precipitation_probability_max,weather_code`, `timezone=auto`, `forecast_days=4`, `latitude`/`longitude`; `temperature_unit=fahrenheit` only in °F mode. Geocoding `https://geocoding-api.open-meteo.com/v1/search?name=<city>&count=1&language=es`.
- No new library dependencies: the JSON is small and fixed, so it is read with a bounded hand-written extractor in the style of the existing parsers, and never with a generic document tree. A dependency addition would be a separate decision.
- Grid: the four cells sit on the canvas separated by whitespace ONLY — S9 removed the two 1 px divider lines, and nothing is ever drawn in column 32 or row 32. Cells are today (top left), +1 (top right), +2 (bottom left), +3 (bottom right), each owning a 31x31 content area with the empty column 31/row 31 strips as the separation. Each cell (S7) draws the three-letter day label (`HOY`, then `LUN`..`DOM` from the RTC) at scale 1 with the precipitation probability `NN%` right-aligned on that same top row — the `%` glyph ends at the cell's own edge, column x0+30 — then the maximum at scale 2 and the minimum at scale 2 (same size), and (S8/S9) an 8x8 icon derived from the day's WMO weather code in the eight columns x0+19..x0+26 (4 px further left than the first revision had) over the vertical middle rows (y0+14..y0+21). The icon is drawn only when BOTH temperature figures fit beside it: any three-character figure omits the icon and keeps the FULL number, never truncating a digit (the sign no longer costs a glyph cell, because S9 removed it). All through the shared brightness helper and the same 3x5 glyph table the clock uses; the icons use the same plot discipline with their own row-byte table.
- WMO grouping (S8): seven groups — clear (code 0), partly cloudy (1..2), cloudy (3), fog (45, 48), rain (51..57, 61..67, 80..82), snow (71..77, 85, 86), storm (95..99) — with everything else, including the gaps 46/47 and any code outside the table, in an explicit unknown state that shows no icon. The seven bitmaps: sun disc, sun behind cloud, two-puff cloud, three staggered bars, cloud with falling strokes, cloud with grains, cloud with bolt.
- Alternation: the clock and the weather screen alternate while in clock mode, driven by the same monotonic tick the clock animation already uses, with the two durations read from settings. The weather screen is shown only when a forecast has been received at least once; until then the clock stays on screen, so a board without internet or without a city never flickers to an empty grid.
- Fetch: once the station is connected, then every 30 minutes, with a bounded connect/read timeout; a failed fetch keeps the previous forecast and never blocks the main loop. Requests are made only while connected; nothing is fetched in portal or AP mode.
- Settings, persisted in `gentle` with read-back verification and the same verified-transaction discipline already used: `clocksecs` (5..120 step 5, default 20), `weathersecs` (5..120 step 5, default 10), `units` (0 = Celsius default, 1 = Fahrenheit), `citylat`, `citylon` (integers of micro-degrees to avoid float persistence), `cityname` (up to 24 bytes). None of these keys is in the DOWN-reset scope.
- Portal `/config` gains a city text field with its own search action, the two duration fields and the unit choice, all validated with a reason on rejection and stored through the verified transaction; an invalid or failed search changes nothing.
- Sign encoding (S9): a negative figure loses its minus glyph and is painted in intense blue, so the colour carries the sign. To keep that unambiguous, the positive minimum changes from blue to the muted ink: colour now means sign, and brightness inside the cell still separates the primary maximum from the secondary minimum. The icon slot moves 4 px left, and the two divider lines are gone, leaving the four cells separated by whitespace only.
- Default city: `Sevilla`, latitud `37382830` y longitud `-5973170` en micro-grados, exactamente lo que devuelve la geocodificación de Open-Meteo para `name=Sevilla&language=es` (37.38283, -5.97317, zona `Europe/Madrid`). Es el valor inicial cuando no hay ciudad guardada, y no hace falta ninguna llamada de red para tenerlo.
- `/health` gains additive fields only: `weather` (whether a forecast is currently held) and the resolved city name. No existing field changes meaning.
- No new serial console command, and no change to `/emote`, the session controls, the PNG path, the diagnostics overlay, the Wi-Fi info overlay or the AP portal's existing routes.
