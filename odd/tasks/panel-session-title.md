# Panel session title (parity with the desktop utility)
Objective: make the ESP32 receiver handle the session title exactly as the desktop receiver does, and show it on the panel clock. No device write or publication.
Branches: `feat/panel-session-title` in the firmware repository, branched from `1432192`; the sender half landed directly on `main` because that repository's feature branch was removed when its integration was published, and the peer session that owns that repository carries it from now on. Delivery: local Conventional Commits with tests and docs; no push, no PR, no flash. Runners: firmware `PATH="$PWD/.tools/llvm-mingw/bin:$PATH" python -m unittest discover -s tests -v`; sender `npm test`.

## Specs
S1. User: "revisa contra la utilidad deescritorio como se gestiona la recepcion del titulo de la sesion que se envia desde gentle-emotex para implementarlo de igual modo", then selected "Receptor firmware (paridad completa)". The desktop mechanism to reproduce is the one mapped in this session from `D:/Desarrollo/gentle-emote-desktop`: receive `X-Emote-Project-Name`, validate it, bind it to the accepted frame and session, keep it until a later image omits it, and paint it on the clock.
S2. Desktop parity rules to reproduce verbatim, from `src/receiver.rs:265-311`, `src/sessions.rs:200-279` and `src/idle_clock_image.rs:186-217`:
- Percent-decode exactly once; `+` is literal, not a space. `%` requires two hex digits.
- Reject with `400` and the body `invalid project name\n`: a second `X-Emote-Project-Name` header; header bytes that are not valid UTF-8; encoded length above 1152 ASCII bytes; a decoded length above 384 UTF-8 bytes; malformed escapes; decoded bytes that are not valid UTF-8; blank after trimming; more than 128 UTF-16 units; exactly `.` or `..`; any character `<= \u{1f}`, `\u{7f}`, `/` or `\`. A rejected request changes nothing.
- The name commits only with an accepted image, after decoding and the admission decision; a later accepted image without the header clears it.
- `heartbeat`/`release`/`claim` ignore the header and never change the stored name.
- Clock title: uppercase, at most 16 cells, 17 or more becomes 13 cells plus `...`, centered, 3x5 glyphs at scale 1 with 4 px advance, muted ink, drawn into the alternating top band of rows 1..5 defined by S5, never over the date in the same phase, and every other row keeps its current content.
- No accepted frame or heartbeat for more than 15 s while the clock is shown => the title reads `*NO SESSION*`; the next accepted frame or heartbeat restores it.

Desktop rule from `D:/Desarrollo/gentle-emote-desktop/src/idle_clock_image.rs:178-217`: the top band is rows 1..5, where the date already sits at x=12, y=1; while `floor(epoch_millis / 5000) mod 2 == 0` the band keeps the centered `DD/MM/YYYY` date, and in the other phase it shows the title instead (ASCII-uppercased, at most 16 cells, 17 or more becomes 13 cells plus `...`, centered with `(64 - (cells * 4 - 1)) / 2`, 3x5 glyphs at scale 1, muted ink, y=1); an empty or absent name always shows the date; the phase comes from the absolute epoch so every screen flips together; every pixel outside rows 1..5 keeps the canonical clock content, and the daunting staleness rule still turns the title phase into `*NO SESSION*` after 15 s.

## Implementation decisions
- Validation lives in a firmware helper (`include/project_name.h`) mirroring the desktop matrix, so the parser stays readable; the parser returns a distinct rejection for an invalid name, and `parseHeaders` maps it to 400 while the runtime answers with `invalid project name\n`.
- The accepted name is stored only by the image path, after the ownership admission decision and after successful presentation, so a rejected foreign or invalid image never renames the display. A single NUL-terminated 385-byte buffer is enough (384 decoded bytes plus terminator); no UTF-16 storage is needed because the 128-unit bound is validated on the decoded UTF-8 directly (a UTF-8 scalar never exceeds a UTF-16 unit count for the accepted ASCII-and-letters range; validate against the desktop rule, not an approximation).
- Liveness for `*NO SESSION*` uses one timestamp updated by an accepted image and by any successful control call, never by rejected traffic.
- The letter glyph table extends the existing digits-only table; digits, `/` and `:` keep their current bitmaps so the date, time and walkers do not move.
